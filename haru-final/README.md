# 하루 — 계정별 서버 저장 버전

업무·목표·시간·일기·건강·관계·투자·대출을 한곳에서 기록하고 홈에서 요약하는 개인 대시보드입니다.

이 버전은 Supabase 로그인과 계정별 서버 저장을 연결한 정적 웹앱입니다. 프로젝트 주소와 공개용 키는 `config.js`에 반영되어 있습니다. 관리자용 비밀 키는 포함하지 않습니다.

**먼저 `SUPABASE_SETUP.md`의 SQL 2개 실행과 본인 로그인 계정 등록을 완료해야 합니다.** 프로젝트를 생성한 것만으로 데이터베이스 설정이 실행되지는 않습니다.

## 배포 파일

`index.html`, `styles.css`, `app.js`, `cloud.js`, `calendar.js`, `income-format.js`, `config.js`를 같은 폴더에 두고 GitHub Pages 등으로 제공합니다. 설치·빌드는 필요 없습니다. 현재 파일은 GitHub에 자동 업로드하지 않았습니다.

실행 명령: 이 폴더에서 `python3 -m http.server 8020 --bind 127.0.0.1`

기존 CEO Diary와 초기 시안 파일은 그대로 보존했습니다. 각 클라우드 작업은 격리되어 있으므로 별도 Git worktree를 만들 필요가 없습니다.

## 저장과 로그인

- 로그인 후 본인 계정의 서버 기록을 불러옵니다.
- 저장 중/완료/실패/다른 기기 충돌 상태를 별도로 표시합니다.
- 변경을 보낼 때 버전을 검사하여 다른 기기 기록을 자동으로 덮어쓰지 않습니다.
- 연결 실패 시 계정별 기기 임시 기록을 보관하고 재연결 때 복구합니다.
- 기존 브라우저 기록이나 JSON 백업은 확인 후 계정으로 가져올 수 있습니다.
- `?demo=1`은 별도 로컬 데모입니다. 실제 계정에 예시 데이터를 보내지 않습니다.

전체 기록 문서 한 개를 계정별로 저장하는 초기 개인용 구조입니다. 충돌 시 자동 문장 병합은 하지 않습니다. 대규모 협업용이나 모든 수정 이력을 보관하는 구조는 아닙니다.

## 기능

- 홈: 업무 완료/전체, 목표 준비 단계 완료/전체, 기록 시간, 일기 작성일, 업무별 다음 행동과 시간 배분
- 본업·사이드프로젝트: 투자 회사(이사), 워크스워크, PWR을 기본 활동으로 제공하고 추가·편집 가능
- 목표·버킷리스트: 역할·이유·결과·장애물·실행 계획과 준비 단계 연결
- 성찰 일기: 장면과 감정 → 발견 → 다음 시도. 선택 감사/생각 기록. 주간 점검에서 모아보기
- 건강: 수면·체중·운동 여부·활동 시간·음주·기분. 미기록과 안 함을 구분
- 관계: 함께한 순간·시간·챙길 이슈와 다음 행동
- 돈: 대출과 투자 현황만. 지출·가계부를 요구하지 않음
- 돌아보기: 매일·주간·분기·연간 기록, 홈에서 이어가기, 행동을 할 일로 가져오기
- 주간 흐름: 기록 범위 안에서만 집계하며 실제 시간과 계획, 관계 시간은 섞어 합산하지 않음
- 드러커의 결정·예상 결과·실제 결과·강점과 시간 관찰 도구
- JSON 백업·복원

Google Calendar 읽기 전용 연결을 추가했습니다. 처음에는 `GOOGLE_CALENDAR_SETUP.md`에 따라 공개 OAuth 클라이언트 ID와 Google 동의 설정이 필요합니다. 금융 자동 연동, 사진 첨부, 자동 알림은 아직 없습니다. 저술·연구를 제품에 응용한 범위와 출처는 `SOURCES.md`를 참고하세요.

## 검증

PostgreSQL RLS와 권한·충돌은 실제 PostgreSQL 엔진에서 검증했습니다. 로그인과 기기 간 저장은 API 모사 브라우저 테스트에서 검증했습니다. 실제 프로젝트의 SQL 실행·실계정 로그인·실제 배포 검증은 완료되지 않았습니다. 현재 클라우드 실행 환경에서는 해당 프로젝트 도메인이 네트워크 정책으로 차단되어 있습니다.

테스트와 운영 설정의 상세 내용은 `SUPABASE_SETUP.md`에 있습니다. 과거 로컬 시안의 변경 이력은 `LOCAL_VERSION_NOTES.md`에 보관하며, 현재 저장 방식은 이 README와 설정 안내를 기준으로 합니다.

## Google Calendar 개발 변경

- 최신 main을 기준으로 별도 로컬 브랜치에서 작업했습니다. 사용자 지시에 따라 게시·배포·원격 푸시는 하지 않았습니다.
- 홈과 캘린더 화면의 Google 일정을 읽고, 끝난 일정의 실제 시간만 확인해서 기존 시간 기록으로 가져옵니다.
- Google client secret, 새 Supabase 테이블이나 SQL 변경은 필요 없습니다. 설정·선택은 기존 profile의 선택적 JSON 문자열에 저장합니다.
- `calendar.js`를 다른 배포 파일과 같은 폴더에 포함합니다.
- `tests/google-calendar.cjs`로 모사 Google/Supabase API를 이용한 브라우저 검증을 실행합니다. `HARU_TEST_URL`의 기본값은 테스트 서버 포트 8021입니다.
- 테스트용 Google 응답을 사용한 검증이며 실제 본인 Google 계정 연결은 아직 남아 있습니다.

## Tasks와 확인 후 반영 · 알바

Google Tasks 읽기 전용 선택 연결을 추가했습니다. 불러온 일정·할 일은 검토 전 내 통계에 포함하지 않습니다. Google 원본을 변경하지 않으며 원본 변경도 내 기록에 자동 적용하지 않습니다. Tasks의 제목·분류·기한·메모·완료 여부를 확인해 반영하고 동일 항목은 기존 기록으로 갱신합니다.

알바는 실제 시간 기록의 분류로 저장합니다. 근무처·시급은 선택 입력이며 업무 화면에서 확인한 시간과 시급 입력분의 예상 금액을 봅니다. 실제 입금이나 급여로 자동 처리하지 않습니다. 선택 정보는 접어두어 일반 기록 입력 부담을 줄였습니다.

Google Cloud에서 Calendar API와 함께 Tasks API 활성화 및 선택 읽기 범위 동의가 필요합니다. 자세한 설정·사용·검증은 `GOOGLE_CALENDAR_SETUP.md`에 있습니다. Google 실제 계정 동의와 원격 게시·배포는 아직 수행하지 않았습니다.

## 월별 추가 알바 수입

기존 CEO Diary의 `[알바] … (50)` 표기를 50만원의 건별 총액으로 읽습니다. 사용자 확인 전에는 합산하지 않으며 수행일 기준 확정 수입과 실제 입금일 기준 수입을 구분합니다. 미래 예정과 미입금도 따로 표시합니다. 시급 예상 금액과 제목의 총액을 중복 계산하지 않습니다. 돈 화면에서 월별·연도별로 보고 홈에서도 이번 달 요약을 확인합니다. 지출 기록이나 새 Supabase SQL은 필요하지 않습니다.

배포 파일에 `income-format.js`를 함께 포함합니다. 자세한 규칙과 검증은 `GOOGLE_CALENDAR_SETUP.md`에 있습니다. 아직 원격 게시·배포하지 않았습니다.
