# 시크릿 — 계정별 서버 저장 버전

업무·목표·시간·일기·건강·관계·투자·대출을 한곳에서 기록하고 홈에서 요약하는 개인 대시보드입니다.

이 버전은 Supabase 로그인과 계정별 서버 저장을 연결한 정적 웹앱입니다. 프로젝트 주소와 공개용 키는 `config.js`에 반영되어 있습니다. 관리자용 비밀 키는 포함하지 않습니다.

**먼저 `SUPABASE_SETUP.md`의 SQL 2개 실행과 본인 로그인 계정 등록을 완료해야 합니다.** 프로젝트를 생성한 것만으로 데이터베이스 설정이 실행되지는 않습니다.

## 배포 파일

`index.html`, `styles.css`, `app.js`, `cloud.js`, `calendar.js`, `income-format.js`, `time-stats.js`, `config.js`를 같은 폴더에 두고 GitHub Pages 등으로 제공합니다. 배포에는 같은 폴더의 나머지 기능 스크립트, `work-journal.js`, `manifest.webmanifest`, `icons/`도 포함합니다. 설치·빌드는 필요 없습니다.

실행 명령: 이 폴더에서 `python3 -m http.server 8020 --bind 127.0.0.1`

기존 CEO Diary와 초기 시안 파일은 그대로 보존했습니다. 각 클라우드 작업은 격리되어 있으므로 별도 Git worktree를 만들 필요가 없습니다.

## 저장과 로그인

- 로그인 후 본인 계정의 서버 기록을 불러옵니다.
- 저장 중/완료/실패/다른 기기 충돌 상태를 별도로 표시합니다.
- 변경을 보낼 때 버전을 검사하여 다른 기기 기록을 자동으로 덮어쓰지 않습니다.
- 연결 실패 시 계정별 기기 임시 기록을 보관하고 재연결 때 복구합니다.
- 기존 브라우저 기록이나 JSON 백업은 확인 후 계정으로 가져올 수 있습니다.
- `?demo=1`은 별도 로컬 데모입니다. 실제 계정에 예시 데이터를 보내지 않습니다.

전체 기록 문서 한 개를 계정별로 저장하는 초기 개인용 구조입니다. 충돌 시 자동 문장 병합은 하지 않습니다. 대규모 협업용이나 모든 수정 이력을 보관하는 구조는 아닙니다.

## 기능

- 홈: 업무 완료/전체, 목표 준비 단계 완료/전체, 기록 시간, 일기 작성일, 업무별 다음 행동과 시간 배분
- 업무: 크립톤·워크스워크·PWR의 할 일과 짧은 일지를 우선 표시. 본업/사이드프로젝트 태그는 표시하지 않음
- 목표·버킷리스트: 역할·이유·결과·장애물·실행 계획과 준비 단계 연결
- 성찰 일기: 장면과 감정 → 발견 → 다음 시도. 선택 감사/생각 기록. 주간 점검에서 모아보기
- 건강: 수면·체중·운동 여부·활동 시간·음주·기분. 미기록과 안 함을 구분
- 관계: 함께한 순간·시간·챙길 이슈와 다음 행동
- 돈: 자산 구성·공개 시세 평가·대출·계층형 자금 목표. 지출·가계부를 요구하지 않음
- 돌아보기: 매일·주간·분기·연간 기록, 홈에서 이어가기, 행동을 할 일로 가져오기
- 주간 흐름: 기록 범위 안에서만 집계하며 실제 시간과 계획, 관계 시간은 섞어 합산하지 않음
- 드러커의 결정·예상 결과·실제 결과·강점과 시간 관찰 도구
- JSON 백업·복원

Google Calendar 읽기 전용 연결을 추가했습니다. 처음에는 `GOOGLE_CALENDAR_SETUP.md`에 따라 공개 OAuth 클라이언트 ID와 Google 동의 설정이 필요합니다. 금융 자동 연동, 사진 첨부, 자동 알림은 아직 없습니다. 저술·연구를 제품에 응용한 범위와 출처는 `SOURCES.md`를 참고하세요.

## 검증

PostgreSQL RLS와 권한·충돌은 실제 PostgreSQL 엔진에서 검증했습니다. 로그인과 기기 간 저장은 API 모사 브라우저 테스트에서 검증했습니다. Google/Supabase 연결 동작은 모의 API로 검증하며 실제 사용자 계정의 일정이나 금융 내역을 테스트 데이터로 변경하지 않습니다. GitHub Pages 공개 파일은 배포 후 별도로 확인합니다.

테스트와 운영 설정의 상세 내용은 `SUPABASE_SETUP.md`에 있습니다. 과거 로컬 시안의 변경 이력은 `LOCAL_VERSION_NOTES.md`에 보관하며, 현재 저장 방식은 이 README와 설정 안내를 기준으로 합니다.

## Google Calendar 개발 변경

- 최신 main을 기준으로 별도 로컬 브랜치에서 작업했습니다. 사용자 지시에 따라 게시·배포·원격 푸시는 하지 않았습니다.
- 홈과 캘린더 화면의 Google 일정을 읽고, 끝난 일정의 실제 시간만 확인해서 기존 시간 기록으로 가져옵니다.
- Google client secret, 새 Supabase 테이블이나 SQL 변경은 필요 없습니다. 설정·선택은 기존 profile의 선택적 JSON 문자열에 저장합니다.
- `calendar.js`를 다른 배포 파일과 같은 폴더에 포함합니다.
- `tests/google-calendar.cjs`로 모사 Google/Supabase API를 이용한 브라우저 검증을 실행합니다. `HARU_TEST_URL`의 기본값은 테스트 서버 포트 8021입니다.
- 테스트용 Google 응답을 사용한 검증이며 실제 본인 Google 계정 연결은 아직 남아 있습니다.

## Tasks와 확인 후 반영 · 알바

Google Tasks 읽기 전용 선택 연결을 추가했습니다. 불러온 일정·할 일은 개요의 조회 현황에 자동 표시하고 실제 기록은 확인 후 저장합니다. Google 원본을 변경하지 않으며 원본 변경도 내 기록에 자동 적용하지 않습니다. Tasks의 제목·분류·기한·메모·완료 여부를 확인해 반영하고 동일 항목은 기존 기록으로 갱신합니다.

알바는 실제 시간 기록의 분류로 저장합니다. 근무처·시급은 선택 입력이며 업무 화면에서 확인한 시간과 시급 입력분의 예상 금액을 봅니다. 실제 입금이나 급여로 자동 처리하지 않습니다. 선택 정보는 접어두어 일반 기록 입력 부담을 줄였습니다.

Google Cloud에서 Calendar API와 함께 Tasks API 활성화 및 선택 읽기 범위 동의가 필요합니다. 자세한 설정·사용·검증은 `GOOGLE_CALENDAR_SETUP.md`에 있습니다. Google 실제 계정 동의와 원격 게시·배포는 아직 수행하지 않았습니다.

## 월별 추가 알바 수입

기존 CEO Diary의 `[알바] … (50)` 표기를 50만원의 건별 총액으로 읽습니다. 사용자 확인 전에는 합산하지 않으며 수행일 기준 확정 수입과 실제 입금일 기준 수입을 구분합니다. 미래 예정과 미입금도 따로 표시합니다. 시급 예상 금액과 제목의 총액을 중복 계산하지 않습니다. 돈 화면에서 월별·연도별로 보고 홈에서도 이번 달 요약을 확인합니다. 지출 기록이나 새 Supabase SQL은 필요하지 않습니다.

배포 파일에 `income-format.js`를 함께 포함합니다. 자세한 규칙과 검증은 `GOOGLE_CALENDAR_SETUP.md`에 있습니다. GitHub Pages에서는 `/haru-final/` 주소로 사용합니다.

## 홈 요약과 상세 시간 분석

홈은 핵심 현황과 오늘 일정·할 일의 짧은 미리보기만 보여주고, ‘내 캘린더·상세 시간 분석’으로 이동합니다. 캘린더에는 일정·검토 탭과 상세 시간 분석 탭이 있습니다.

상세 화면은 오늘·주간·월간·지난달·직접 선택한 월(1900~2099)을 지원합니다. 요일에 맞춘 날짜별 기록, 역할별 배분, 예정과 실제를 분리한 시간대 타임라인, 겹치는 실제 구간, 분만 기록하여 위치를 모르는 활동을 봅니다. 시간은 시간·분으로 표시합니다.

시작·종료는 선택입니다. 일정의 예정 시각을 실제 시각으로 자동 간주하지 않으며 명시적으로 확인했을 때만 저장합니다. 실제 구간 길이와 분이 다르면 저장을 막고 조정하거나 시각을 비우도록 안내합니다.

분 합계는 기록일 기준이며 겹칠 수 있습니다. 시각 확인분은 실제 구간을 날짜별로 나누고 합집합으로 계산하여 겹침을 제거합니다. 자정을 넘는 구간은 타임라인 날짜별로 분리되므로 기록일 기준 합계와 다를 수 있습니다. 종일 예정은 시간 합계에서 제외하고 미래 시간은 시각 미확인으로 계산하지 않습니다.

시각 미확인 구간은 수면·휴식·분만 적은 활동 등일 수 있으며 낭비·실패·비생산성을 의미하지 않습니다. 관계·건강의 분량을 실제 시간 기록에 다시 더하지 않습니다. 과거 기록의 실제 시각도 역으로 추정하지 않습니다.

테스트: `node tests/time-stats.cjs`에서 합집합·겹침·시각 없는 기록·경과 시간·종일·자정 분리·입력 검증을 확인합니다. `tests/time-analysis.cjs`는 모사 API 브라우저 검증이며 명시적 시각 확인, 실제 분과 구간 불일치 거부, 월 선택·윤년·모바일 내부 스크롤·서버 보관을 확인합니다. 기존 Google Calendar/Tasks·월별 수입·클라우드 동기화 회귀 검증도 통과했습니다. 실제 Google 계정 인증과 게시·배포는 별개이며 아직 수행하지 않았습니다.


### 관계 · 생일 · 안부

- 이름·별칭만으로 시작하고 생일, 정기 안부 주기, 최근 연락일은 선택 입력합니다.
- 생일은 출생연도 없이 월·일을 보관합니다. 음력은 자동 변환하지 않고 매년 확인한 양력 날짜를 입력합니다. 2월 29일의 평년 표시 방식을 선택할 수 있습니다.
- 사람별 여러 기념일을 매년 또는 일회성으로 등록합니다. 앞으로 30일의 생일·기념일은 관계 화면과 홈(최대 3건)에 표시됩니다.
- ‘오늘 떠올리기’는 연락 계획입니다. 실제 연락을 확인해 저장한 기록만 최근 연락일과 정기 안부 계산에 반영됩니다. 연락 기록 수정·삭제 시 다시 계산하며, 이전에 수동 입력한 최근 연락일은 기준으로 유지됩니다.
- 정기 안부는 미루거나 잠시 쉴 수 있고, 오늘 계획은 넘기거나 다시 추가할 수 있습니다. 자동 메시지·외부 알림·관계 점수·Google 연락처 접근은 없습니다.
- 기존 함께한 순간·관계 이슈를 유지합니다. 기존 JSON 계정 저장과 호환되며 추가 SQL은 필요 없습니다.
- 검증: `node tests/relationship-dates.cjs`, Playwright `tests/relationships.cjs`, `tests/relationships-cloud.cjs`(모의 Supabase). 실제 외부 계정 접속 검증은 아닙니다.


### 자금 목표와 월간 점검

지출 가계부 없이 목적·목표 금액·기한·실행 계획을 정합니다. 비상자금은 직접 확인한 현금성 확보액, 목적자금/장기 투자는 직접 입력 또는 등록 투자 평가액, 상환 목표는 연결한 대출의 시작 잔액 대비 감소액으로 진행률을 계산합니다. 소득을 저축액에 자동 합산하지 않으며, 여러 목표의 금액도 합산하지 않습니다. 같은 자금을 여러 목표에 쓰지 않도록 화면에 안내합니다.

월 필요액은 남은 금액을 남은 개월 수(월 미만 올림, 최소 1개월)로 나눈 단순 계획값입니다. 이자·수익률·세금은 가정하지 않습니다. 이미 지난 기한에는 월 필요액 대신 재검토를 안내합니다. 원본 기록이 삭제되거나 기준일이 없거나 미래라면 목표 달성을 표시하지 않습니다. 기준일이 45일 넘은 현황은 재확인을 안내합니다.

‘현황 점검’으로 당시 잔액·목표액·잔액 기준일·점검일을 최대 120회 보관합니다. 목표액을 바꿔도 과거 점검 당시 목표액을 유지합니다. 대출/투자 연결 목표는 원본 값으로 진행률을 갱신하되 점검 이력은 사용자가 확인할 때만 남깁니다. 목표는 `profile.moneyPlan` JSON 문자열로 기존 계정 저장·백업과 호환되며 추가 SQL이 없습니다.

근거와 예시는 돈 화면의 접힌 설명에서 확인할 수 있습니다. CFPB의 Your Money, Your Goals 도구(목표 설정·실행·재검토)와 비상자금 가이드(안전성과 접근성·정기 적립·진행 확인)를 응용했습니다. Thaler & Benartzi (2004), Save More Tomorrow, DOI 10.1086/380085는 미래 급여 인상 시 저축 증액을 미리 약속하는 직원 퇴직저축 연구입니다. 불규칙 추가 수입에 배분 규칙을 쓰는 것은 이 앱의 응용이며 같은 효과가 검증됐다고 주장하지 않습니다. CFPB 원문은 확인했고 해당 연구의 서지는 Crossref로 확인했습니다(저널 본문 접근은 제한됨).

검증: `node tests/money-goals.cjs`, Playwright `tests/money-goals-browser.cjs`(모의 Supabase 계정 저장). 실제 계정 금융 연동·송금·자동 이체 기능은 없습니다.


### Google 연결 유지와 화면 개선

홈의 Google 일정/Tasks는 검토 대기 항목을 각각 최대 2개로 요약합니다. 항목을 확인해 반영하거나 하루 목록에서만 숨길 수 있고 캘린더에서 복원합니다. 숨겨도 Google 원본·확정 기록·시간 분석의 원본 계획 데이터는 유지됩니다. 캘린더 탭은 주간 시간표와 날짜별/월간 시각화가 기본이며 상세 목록은 접혀 있습니다.

새로고침은 계정/클라이언트/만료일을 확인해 탭 세션을 복원합니다. 접근 토큰은 sessionStorage에만 두고 로그아웃 시 삭제합니다. 장기 자동 갱신은 `supabase/003_google_connections.sql`과 `supabase/functions/google-connect/index.ts` 및 Google 보안 키 설정이 필요합니다. 관리자 절차는 [장기 연결 설정](supabase/GOOGLE_PERSISTENT_SETUP.md)을 참고하세요. 해당 서버 설정 없이 무기한 연결되는 것은 아닙니다.


`메모` 캘린더는 일정과 분리합니다. 연결 설정에서 표시 방식을 선택할 수 있습니다. 메모는 홈/날짜별 메모에 표시하고 시간표·시간 통계·알바 수입 후보에서 제외합니다. 확인한 메모만 자유 기록으로 가져오며 추가 SQL·Google 권한은 필요 없습니다.


### Google 중심 업무·목표·시간 자동 연결

MY LIFE OVERVIEW, 업무 현황, 목표 카드, 주간 시간은 Google 조회 완료 시 자동 갱신합니다. 선택한 Tasks 목록의 완료 항목까지 읽고, 원본 식별자가 같은 내부 기록은 중복 집계하지 않습니다. 내부에서 수정한 내용이 우선이며 원본 완료 상태 변경은 업무 화면의 ‘Google 변경 검토’로 안내합니다. 조회 실패/미연결과 부분 조회를 구분하고 자동 집계가 일기나 실제 시간을 새로 저장하지는 않습니다.

연결 설정에서 캘린더별, Tasks 목록별 기본 활동·목표를 지정하면 이후 항목에 적용합니다. 활동 이름과 캘린더/목록 이름이 정확히 하나만 일치하면 기본 활동을 자동 연결합니다. 목표는 추측하지 않고 사용자가 연결합니다. 연결한 목표에 소속 활동이 있으면 그 활동을 따릅니다. 미래 일정을 포함한 개별 일정은 ‘활동·목표 연결’에서 기본값을 바꾸거나 해제할 수 있고, 이 설정은 Google 원본이나 실제 시간을 바꾸지 않습니다. Tasks 반영과 실제 시간 기록에서도 목표를 수정할 수 있습니다.

목표 카드에는 연결된 할 일의 완료 단계와 이번 주 예정/실제 시간을 표시합니다. 단계 완료를 목표 자체의 달성으로 자동 확정하지 않습니다. 캘린더 메모·종일은 예정 시간 합계에서 제외하고 겹침을 제거합니다. 종료된 일정은 ‘지난 일정 기준 추정’으로 별도 표시해 실제 확인 기록과 합산하지 않습니다. 캘린더 화면에서 지난달을 보더라도 홈의 주간 데이터는 별도로 조회합니다. 자동 갱신은 집계 영역만 바꾸므로 주간 점검 등 작성 중인 입력 내용을 유지합니다.

설정은 기존 계정 JSON(profile.googleCalendar), 개별 목표 연결은 기존 tasks/timeLogs의 선택 문자열 필드로 저장하며 추가 SQL이나 Google 쓰기 권한이 필요 없습니다. 검증은 `tests/life-overview.cjs`, `tests/life-overview-browser.cjs`의 모의 Google/Supabase를 사용합니다.


### 각 탭의 기록 메모

별도 ‘설계 근거’ 버튼과 전문가 목록 페이지를 제거하고 `method-notes.js`의 메모를 실제 사용 위치에 배치했습니다. 홈(코비), 캘린더(드러커), 기록(GTD), 목표(WOOP·실행 의도), 업무(기여), 돈(자금 목표·적립), 건강(포그), 관계(자기결정성이론), 일기(깁스), 돌아보기·결정(피드백 분석)에 저자의 접근·왜 사용하는지·이 탭에서 해볼 행동을 함께 표시합니다. 감사·생각 기록의 근거는 해당 선택 입력 바로 옆에 둡니다.

핵심 메모는 항상 보이고 출처·적용 범위만 같은 메모 안에서 펼칩니다. 원문 인용과 앱의 요약/예시를 혼동하지 않도록 표기하며, 이 앱의 축약 조합이 검증됐다고 주장하지 않습니다. 사용자 데이터에 안내 문구를 기록으로 추가하거나 입력 항목을 늘리지는 않습니다. 기존 `#guide` 링크는 홈으로 돌아갑니다. 배포에는 `method-notes.js`를 함께 포함합니다.


### Google Tasks 시각형 보드

캘린더와 할 일 보드에서 개인·업무·기타 세 칸으로 표시합니다. 오늘/이번 주/다음 주/월/선택 월의 조회 범위를 공유하며 기한은 시작일 포함·종료일 제외로 필터링합니다. 날짜 없는 할 일은 별도 접힌 영역에 모아 기간별 결과와 섞지 않습니다. 카드에는 제목·기한·분류와 필요한 동작만 표시하며 목록 이름·반영 상태·목표 설명은 반복하지 않습니다. 6개 이후는 펼쳐서 확인합니다.

카드 분류가 목록 기본 분류보다 우선합니다. 업무는 크립톤(invest)·워크스워크(works)·PWR(pwr) 중 고릅니다. `profile.googleCalendar.taskItemRoles`에 카드별 회사 선택을 저장하며 원본 Google 목록을 이동하지 않습니다. 기존 가족 분류는 개인, 메모 분류는 기타로 표시합니다. 기존 메모 목록은 계속 notes로 가져오고 시간·수입을 자동 생성하지 않습니다. 기존 내부 기록의 사용자가 확인한 값도 임의로 덮어쓰지 않습니다.

검증: `tests/google-task-board.cjs`는 모의 Google/Supabase로 기간 경계·다음 주·선택 월·날짜 없음 분리, 세 분류, 회사 해제/변경/재접속, 메모 보존, 짧은 업무 일지, XSS·모바일·원본 무변경을 확인합니다.

### 시크릿 · 업무 일지와 수입 확인

- Tasks 목록 CDE는 개인, KRP/WSW/PWR은 업무, 가족은 개인, 메모는 기타로 표시합니다. 해당 기본 역할이 존재하면 함께 연결합니다. 새로 발견한 이 이름의 목록은 한 번 자동 선택하며 이후 수동 선택과 분류를 유지합니다.
- 업무 일지는 본업·프로젝트 / 정기 알바 / 단기 알바 / 투자 검토로 나눕니다. 기관·요청 담당자·대상 기업·완료/전체 회차·마감·미팅 및 일지 상태를 필요한 만큼 기록합니다. 예시 월간 일지는 구조만 반영하며 실제 8월 실적으로 저장하지 않습니다.
- 업무 화면에서 일반 업무 일정/Tasks도 확인 후 프로젝트로 연결합니다. 알바는 돈 화면에서도 월별 후보를 조회합니다. `[알바] 제목 (50)`은 50만원이며 발표·멘토링·서류 등 명시된 보수와 회차 표기도 제안합니다. 메모는 제외합니다. 원본만 조회해도 수입·실제 시간이 자동 저장되지는 않습니다.
- 수입 확인 시 기관·담당자·정기/단기·귀속 월·금액·예정/확정을 수정할 수 있습니다. 같은 정기 프로그램의 여러 일정은 기존 프로젝트를 선택하면 월 수입 한 건에 연결되어 계약 총액을 회차마다 더하지 않습니다. 다른 달은 별도로 확인합니다. 프로젝트 연결만으로 돈이 기록되지는 않습니다.
- 이번 달 실제 입금·미수금 입력/요약을 제거했습니다. 확인한 추가 수입과 예정 수입만 월별/연도별 조회하며 과거 입금 데이터는 삭제하지 않습니다. 투자·대출·자금 목표는 유지합니다.
- 서비스 표시명은 시크릿입니다. 파란색 시크릿 아이콘과 홈화면 manifest를 제공합니다. 기존 계정·저장 키·OAuth 주소·배포 경로는 유지합니다. 기존 홈화면 아이콘은 삭제 후 다시 추가해야 갱신될 수 있습니다.
- 검증: `tests/work-journal.cjs`, `tests/secret-work-browser.cjs`, `tests/calendar-income.cjs`. 브라우저 검증은 모의 Google/Supabase를 사용합니다.


### 매일 쓰는 화면과 Google 원본 편집

탐색 순서는 캘린더 → 업무 → 기록 → 홈 → 목표·꿈 → 돈 → 관계 → 건강 → 돌아보기입니다. 펼친 수입 후보도 기본 후보와 같은 제목/원본/날짜/금액/확인 버튼을 사용합니다. 업무 일지는 두 열의 동일한 구역 카드로 배치하고 작은 화면에서는 한 열로 전환합니다.

기록에는 메모·책·영화·기타 감상 필터와 제목/창작자/감상 검색이 있습니다. 책·영화는 제목·날짜만으로 시작하며 저자·감독·상태·평점·적용할 한 가지는 선택입니다. 기존 notes 배열의 선택 문자열 필드를 사용해 기존 메모/백업과 호환합니다.

Google 읽기 연결은 그대로 사용할 수 있고 **추가·수정 권한 연결**을 누를 때 Calendar `calendar.events`, Tasks 사용 시 `tasks` 범위를 추가 요청합니다. 실제 응답 범위로 읽기/수정 상태를 표시합니다. `google-editor.js`를 함께 배포해야 합니다.

캘린더에서 **＋ Google 일정**, 보드에서 **＋ Google 할 일**, 각 항목의 **Google … 수정**으로 원본을 편집합니다. 일정은 한국 시간·종일·장소·설명, Tasks는 기한(비우면 없음)·상세·완료 상태를 수정합니다. 공유 캘린더는 owner/writer만 편집할 수 있고 반복 일정은 선택한 회차만 수정합니다. 참석자·공유·반복 규칙 편집은 제공하지 않습니다. 원본 삭제는 편집 창에서 별도 확인 후 실행합니다. PATCH로 편집한 필드만 전송하고 최신 원본의 ETag/If-Match로 충돌을 막습니다. 초대 알림은 보내지 않습니다. 실패 시 자동 재시도하지 않으며 응답 불명 시 중복 추가 방지를 위해 저장 버튼을 잠급니다.

Google 원본 저장과 시크릿의 실제 시간/수입/업무 반영은 구분합니다. Google 저장 후 원본 집계를 새로 조회하되 이미 확인한 로컬 기록은 덮어쓰지 않습니다. 장기 연결의 쓰기 유지에는 최신 `supabase/functions/google-connect/index.ts`를 별도 배포하고 수정 동의를 다시 받아야 합니다. 웹 GitHub Pages 배포가 Supabase 함수까지 배포하지는 않습니다.

검증: `tests/google-write-notes.cjs`(모의 API 원본 POST/PATCH·권한·동시 수정·반복 회차·날짜/완료·기록 저장·전체 탭 모바일), `tests/google-server.cjs`(장기 연결 선택적 수정 범위와 기존 보안 동작).


### 원본 삭제 · 맞춤 기록 분류 · 생활 리듬

- Google 항목의 ‘수정·삭제’ → ‘Google 원본 삭제’에서 대상과 영향을 확인한 뒤 DELETE를 전송합니다. 기존 수정 범위(calendar.events/tasks)에 삭제가 포함되어 별도 범위를 추가하지 않습니다. 최신 원본 ETag로 충돌을 막고 204 성공 응답을 처리합니다. 반복 일정은 선택 회차, Tasks는 선택 항목(하위 할 일이 있으면 함께 삭제될 수 있음)이 대상입니다. 내 기록 숨기기와 구분하며 저장한 시크릿의 실제 시간·수입·메모는 삭제하지 않습니다.
- 기록의 중복 책/영화 추가 버튼을 제거하고 분류 필터와 ‘＋ 기록’으로 통합했습니다. 분류 편집에서 이름·순서·입력 양식(메모/책/영화/기타 감상)을 바꾸거나 추가합니다. 삭제한 분류의 기록은 지정한 남은 분류로 이동하고 내용·메타데이터는 보존합니다. 설정은 profile.noteCategories의 JSON 문자열입니다.
- 평점·감상을 앞에 두고 저자·상태·적용할 행동·역할은 선택 상세 영역으로 접었습니다. 책/영화 제목 입력 후 공개 검색으로 정보를 제안합니다. 유일한 제목 일치는 자동 채우고 동명 후보는 사용자가 고릅니다. 도서: Google Books → Open Library → 위키백과, 영화: Apple iTunes → 위키백과. 응답 제한·실패·누락 시 제목만 저장할 수 있습니다. 모든 작품의 정보를 보장하지 않습니다. 검색에는 제목만 보내며 평점·감상·로그인 토큰은 보내지 않습니다. 자동 작품 소개와 내 감상은 별도 필드로 저장하며 출처를 표시합니다. 정보는 저장 버튼 전에는 계정에 반영하지 않습니다.
- 건강에 잠든/일어난 날짜·시각(KST)을 추가합니다. 기록 날짜는 기상일이며 양쪽 시각이 있으면 실제 경과 분과 시간을 계산합니다. 0분 이하·24시간 초과·미래·기상일 불일치를 거부합니다. 시각 미상의 기존 수면 시간 기록도 유지합니다. 중간 각성 시간은 측정하지 않으며 계산값은 두 시각 사이 시간입니다. 최근 7일과 취침/기상 목표를 표시하며 기상 목표 ±30분 비교는 제품 기준입니다. 목표는 profile.sleepPlan 문자열, 시각은 기존 health 배열의 선택 문자열 필드로 저장합니다.
- 탭 가이드는 고정 내용임을 명확히 하고 페이지 하단의 접힌 ‘기록 방법·출처’로 이동했습니다. 작성 중 사용하는 일기/감사/생각 기록의 인라인 가이드도 기본 접힘이며 입력 위치에 유지합니다. 전문가 출처·이유·예시는 삭제하지 않았습니다.
- 추가 배포 파일: media-lookup.js, sleep-rhythm.js. SQL·Supabase 함수 변경은 없습니다. 기존 Google 장기 연결이 수정 범위로 갱신되려면 앞선 서버 업데이트가 필요하지만 이번 삭제 기능에 추가 서버 변경은 없습니다.
- 검증: tests/sleep-rhythm.cjs, tests/daily-improvements.cjs(모의 Google/메타데이터/Supabase). 공개 검색 API는 별도 실제 요청으로 CORS와 응답을 확인했으며 Google Books의 429 및 iTunes 결과 없음 때문에 대체 조회를 제공합니다.


### 탭 상단 대시보드 · 홈 우선 탐색

탐색 순서는 홈 → 캘린더 → 업무 → 기록 → 목표·꿈 → 돈 → 관계 → 건강 → 돌아보기입니다. 홈은 기존 핵심 현황 4개를 상단으로 옮기고 ‘이번 주 한 걸음’ 배너와 관련 가이드를 제거했습니다. 같은 요약을 추가로 중복 표시하지 않습니다. 나머지 탭은 tab-dashboard.js가 내 기록과 Google 조회 상태를 읽어 요약·그래프를 제공합니다. 이 투영만으로 계정 데이터를 저장하지 않습니다.

- 기록: 최근 30일 기록일(하루 여러 기록은 1일), 이전 30일과의 차이, 기록 건수, 완료 감상 건수, 최근 감상일, 28일 기록 달력, 분류 비중, 최근 완료 기록. 기록 날짜 기준이며 감상은 완료 상태만 포함합니다. 미래 날짜를 제외하고 필터와 관계없이 전체 기록을 집계합니다.
- 목표: 결과 지표·준비 단계 완료율·다음 행동·실제 목표 시간을 구분합니다. 지표 미설정은 달성률 0%로 단정하지 않습니다. ‘결과 지표 설정’에서 완료한 책/영화, 목표에 연결한 실제 시간, 전체 완료 단계와 한 번 연결하거나 확인한 수치를 입력합니다. 책/영화는 지정 시작일 이후의 완료 작품이며 같은 출처 ID 또는 정규화한 작품 제목+저자가 같으면 중복 제외합니다. 시간은 기록일 기준의 확인한 분 합계이며, 완료 단계는 완료 날짜를 추정하지 않고 전체 연결 단계 기준입니다. 직접 확인한 수치는 증가·감소 목표 모두 지원합니다. 수치 도달과 목표 자체 달성 확정은 구분합니다. 설정은 기존 goals 배열의 선택 문자열 필드로 저장하며 SQL 변경이 없습니다.
- 캘린더: 현재 조회 기간의 일정·겹침 제외 예정 시간·실제 기록 시간, 예정/실제 분포, 다음 일정. 미연결/조회 실패는 미조회로 표시합니다. 실제 시간 분 합계와 예정의 겹침 제외 기준을 표기합니다.
- 업무: 전체 연결 할 일의 남은 개수·완료 단계, 이번 주 기한·활동별 실제 시간, 선택 월의 업무 일지 건수와 주간 분포. Google 원본과 내 기록은 기존 식별자로 중복 제거한 모델을 사용합니다.
- 돈: 확인한 수입과 예정 수입을 구분한 6개월 추이, 등록 투자·확인된 대출 잔액, 자금 목표별 확보액 진행. 투자·대출을 순자산으로 상계하거나 여러 자금 목표를 합산하지 않습니다.
- 건강: 기록한 날만의 7일 평균 수면, 기상 목표와의 비교, 기록일·활동 시간, 수면 추이와 최근 시각. 미기록 수면을 0시간으로 평균에 포함하지 않습니다.
- 관계: 최근 30일 실제 연락과 앞으로 30일 기념일, 오늘 떠올린 사람, 열린 이슈, 4주 연락 기록 분포. 계획만으로 연락일을 만들거나 관계 점수를 계산하지 않습니다.
- 돌아보기: 최근 30일 일기 작성일·최근 일기, 올해 주간 점검, 확인 기한이 지난 결정, 28일 성찰 달력과 최근 다음 시도. 글 길이·감정으로 품질 점수를 만들지 않습니다.

Google 조회/연결 설정 변경 시 해당 집계 영역만 갱신해 입력 중인 폼은 유지합니다. PC와 모바일의 열 수를 조정하고 그래프에 단위·기간·텍스트 설명을 함께 제공합니다.

### 비공개 대출 자료 가져오기

loan-import.js는 사용자가 제공한 JSON 파일 또는 URL fragment의 private payload를 검토 후 로그인 계정에만 반영합니다. 사이트 저장소에는 실제 사용자 금융 데이터가 포함되지 않습니다. 허용 필드만 읽어 계좌번호 등은 버리며, fragment는 파싱 즉시 주소에서 제거합니다. 가져오기 전에는 저장하지 않으며 취소할 수 있습니다. 같은 importKey의 반복 가져오기는 기존 항목을 갱신하고, 기존 대출을 직접 선택해 연결할 수도 있습니다. 빈 정보는 기존 값을 덮어쓰지 않으며 더 오래된 잔액 기준일의 덮어쓰기를 거부합니다. 공개 서버의 로그/쿼리 파라미터에 금융 payload를 넣지 않습니다. 링크를 공유하면 내용을 전달하는 것이므로 암호화 링크라고 부르지 않습니다.

처음 빌린 원금(original), 확인한 현재 잔액(balance/asof), 화면의 갚은 금액(reportedRepaid), 실제 월 상환액(monthly)을 구분합니다. 잔액이 없는 항목은 원금이나 갚은 금액으로 잔액을 추정하지 않고 미확인으로 남기며 0원으로 합산하지 않습니다. 0원 잔액도 기준일이 있으면 유효한 값입니다. 홈·돈의 합계에는 확인된 잔액 건수와 미확인 건수를 표시합니다. 매월 납부일(paymentDay)은 달력상의 다음 예정일만 계산하며 은행 영업일·실제 출금·이자·원금 감소를 자동 기록하지 않습니다. 실제 월 상환액을 모르면 비워둡니다.

추가 배포 파일: tab-dashboard.js, loan-import.js. 테스트: tests/tab-dashboard.cjs, tests/tab-dashboard-browser.cjs, tests/loan-import.cjs, tests/loan-import-browser.cjs. 브라우저 테스트는 모의 API/계정이며 비공개 입력 파일을 테스트에 전달해도 저장소나 원격 사용자 계정에 금융 데이터를 쓰지 않습니다.


### 자산 구성과 작은 자금 목표

돈 → ＋ 자산에서 비상장 기업 주식, 비상장 투자 펀드, 가상자산, 현금을 등록합니다. 부동산과 기존 기타 자산도 지원합니다. 수량과 단위를 입력하고 평가 방식(확인한 총액, 확인한 단가×수량, 공개 시세, 현금 환산)을 선택합니다. 구성 비율은 평가액이 확인된 자산만 분모에 포함하며 미평가 자산은 건수로 표시합니다. 취득원가를 입력한 자산만 평가손익에 포함합니다.

업비트 원화 시장의 가상자산은 공개 가격×수량, USD/EUR/JPY 현금은 Frankfurter의 ECB 기준 환율×수량으로 원화 평가합니다. 시세 출처·가격 기준일·조회 시각을 표시합니다. 환율은 영업일 기준이며 실시간 환전가는 아닙니다. 비상장 주식·펀드는 공개 호가가 보장되지 않으므로 사용자가 확인한 평가액/단가와 기준일을 사용합니다. 가격이 없으면 0원으로 가정하지 않습니다. 합계는 서로 다른 기준일의 확인분 합계이며 순자산이나 모두 오늘 가격이라는 뜻이 아닙니다.

공개 API에는 시장 코드와 통화만 전송하며 보유 수량, 기업명, 계정 정보는 보내지 않습니다. 공개 가격만 세션 캐시하며 계정에 시세를 자동 저장하지 않습니다. 시세는 화면 진입/5분 간격/새로 조회에서 갱신하고, 요청 제한·장애가 생기면 마지막 가격과 지연 상태를 표시합니다. 업비트 요청은 간격을 두고 실행합니다.

자금 목표의 ‘＋ 작은 목표’로 최종 목표 아래에 세부 목표를 연결합니다. 원·만원·억원·채·개·주 등 단위를 편집할 수 있고, 배당 목표는 원/월·만원/월·원/년 등을 사용합니다. 전체 평가액, 자산 유형별 평가액, 개별 자산 평가액/수량, 지역별 부동산 수량과 연결할 수 있습니다. 서울 부동산은 자산 소재지에 ‘서울’을 입력하고 수량을 등록합니다. 확인한 연간 배당·분배금을 월 단위로 표시할 때는 12로 나눈 월평균이며 실제 월 지급액이나 예상 수익률이 아닙니다. 서로 다른 단위의 자녀 목표를 합산하지 않습니다. 점검 이력은 당시 단위를 보관합니다.

검증: `node tests/asset-model.cjs`, `node tests/money-goals.cjs`, Playwright `tests/portfolio-browser.cjs`. 브라우저 검증에는 가상의 자산·계정과 모의 시세만 사용합니다.


### 간단한 업무 일지

업무는 회사별 진행 중 할 일 최대 3개와 일지를 먼저 보여줍니다. 내 역할은 짧은 요약으로, 연결 목표는 펼친 목록으로 표시합니다. 프로젝트·계약 관리, 구글 가져오기, 알바 기록과 통계는 접힌 영역에서 필요할 때 확인합니다. 기존 프로젝트·수입·시간·목표는 보존합니다.

‘＋ 업무 기록’에서 날짜·업무·한 일을 입력하고 결과/배운 점·다음 행동은 선택으로 남깁니다. 일지는 `profile.workEntries` JSON 문자열로 계정에 저장하고 회사/월별로 조회·수정·삭제합니다. 업무 완료나 일지 입력을 실제 시간·수입으로 자동 환산하지 않습니다. 계약 관리는 기관·회차·보고서 상태 등의 상세 입력을 펼쳐서 사용합니다.


### 홈 우선순위와 정렬

상단은 오늘 일정·Google Tasks·건강/습관 세 카드이며 데스크톱/태블릿에서 같은 높이로 정렬하고 모바일에서는 한 열로 표시합니다. 연결 전에도 자리를 유지합니다. 건강은 오늘의 수면·활동·음주·컨디션을 표시하고 기존 건강 기록 폼으로 추가/수정합니다. 미기록을 0이나 실패로 바꾸지 않습니다.

다음 행은 회사별 진행 중 업무(최대 2개씩)와 오늘 하루 한 줄입니다. 업무에는 주간 일정 수·실제 시간·미지정 안내를 반복하지 않고 별도 홈 시간 카드도 제거했습니다. 시간 분석은 캘린더에 남아 있습니다. 카드 행은 일정한 간격을 사용하고 비동기 새로고침에 따른 등장 애니메이션으로 줄이 어긋나지 않도록 고정했습니다.

검증: `tests/home-layout-browser.cjs`에서 실제 브라우저 좌표로 카드 높이/상단/여백, 건강 기록 추가·당일 수정·복원, 입력 중 Google 갱신, 모바일 순서와 넘침을 확인합니다. 모두 가상 계정/모의 Google 데이터입니다.
