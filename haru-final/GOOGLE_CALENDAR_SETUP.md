# Google Calendar 연결 — 처음 한 번 설정

Google 연결 기능은 배포 파일에 포함됩니다. 실제 Google 계정 인증에는 아래의 본인 Google 설정과 공개 OAuth 클라이언트 ID가 필요합니다. 코드만으로 사용자 동의를 대신하거나 기존 Google 계정 권한을 얻을 수는 없습니다.

## 먼저 할 일

1. https://console.cloud.google.com/apis/library/calendar-json.googleapis.com 에 접속합니다.
2. 상단에서 사용할 프로젝트를 선택합니다. 없다면 새 프로젝트를 만듭니다. 이름은 `하루 다이어리` 등으로 자유롭게 정합니다.
3. **Google Calendar API → 사용 / Enable**을 누릅니다. 이미 `관리 / Manage`로 보이면 활성화된 것입니다.

여기까지 하고 다음 설정으로 넘어갑니다. Supabase에서 다시 SQL을 실행하거나 로그인 방식을 바꿀 필요는 없습니다.

## Google 로그인 동의 설정

Google Cloud Console의 **Google Auth Platform**에서 설정합니다. 콘솔 버전에 따라 **API 및 서비스 → OAuth 동의 화면**으로 표시될 수도 있습니다.

1. **브랜딩 / Branding**: 앱 이름을 `하루`로 정하고 본인 이메일을 지원·연락 이메일로 지정합니다.
2. **대상 / Audience**: 개인 Google 계정이라면 보통 External을 선택합니다. 테스트 상태에서 **테스트 사용자**에 실제 캘린더를 사용할 본인 Google 이메일을 추가합니다.
3. **데이터 액세스 / Data Access**에서 다음 읽기 전용 범위를 확인·등록합니다.
   - `https://www.googleapis.com/auth/calendar.events.readonly`
   - `https://www.googleapis.com/auth/calendar.calendarlist.readonly`

일정 작성·삭제, Gmail·연락처, 드라이브 접근은 요청하지 않습니다. 조직 Google Workspace 계정에서는 관리자 정책이 연결을 제한할 수 있습니다.

## 공개 클라이언트 ID 만들기

1. **클라이언트 / Clients → 클라이언트 만들기**로 이동합니다. 예전 콘솔에서는 **사용자 인증 정보 → OAuth 클라이언트 ID 만들기**입니다.
2. 애플리케이션 유형을 **웹 애플리케이션**으로 선택합니다.
3. **승인된 JavaScript 원본**에 다음을 추가합니다.

   ```text
   https://choide88.github.io
   ```

   `/ceo-diary/haru-final/` 경로를 붙이지 않습니다. 다른 도메인에서 실행한다면 그 사이트의 `https://호스트`를 추가합니다.

4. 기본 연결은 브라우저 팝업 모델이며 리디렉션 URI 없이 동작합니다. **장기 연결**은 별도 서버 콜백 URI가 필요합니다. `supabase/GOOGLE_PERSISTENT_SETUP.md`를 참고하세요.
5. 발급된 **클라이언트 ID**를 복사합니다. 모양은 다음과 같습니다.

   ```text
   123456789012-xxxx.apps.googleusercontent.com
   ```

**Client secret은 필요하지 않으며 앱·GitHub·채팅에 넣지 않습니다.** 클라이언트 ID는 공개용이므로 앱의 연결 설정에 입력하거나 개발자에게 전달할 수 있습니다.

개발 검증 시에는 Google 공식 안내에 따라 `http://localhost`와 사용할 포트를 포함한 `http://localhost:8021`을 원본에 별도로 등록하고, 해당 원본에서 실행합니다. 운영 도메인 설정과 개발 원본 설정은 서로 별개입니다.

## 앱에서 연결하기 — 변경을 배포한 뒤

1. 기존 Supabase 계정으로 하루에 로그인합니다.
2. 홈의 **Google Calendar → 처음 연결하기**를 누릅니다.
3. 위 공개 클라이언트 ID를 입력해 저장합니다. ID와 캘린더 선택은 기존 계정 저장소에 보관되므로 다른 기기에서도 사용할 수 있습니다. 공통 ID를 배포 설정 `config.js`의 `googleClientId`에 넣을 수도 있습니다.
4. **Google Calendar 연결**을 누르고 본인 Google 계정을 선택합니다.
5. 일정과 캘린더 목록의 **읽기 권한 두 가지**에 동의합니다.
6. **캘린더 선택**에서 표시할 캘린더를 고릅니다. 투자 회사·워크스워크·PWR 등 기본 활동을 매핑하면 확인 화면에 분류가 채워집니다.

개인 테스트 중이라면 Google에서 지정한 본인 테스트 계정을 사용합니다. 테스트 사용자가 아니거나 프로젝트·출처 설정이 맞지 않으면 연결이 거부될 수 있습니다. 본인 프로젝트가 맞는지 확인하고 오류 안내에 따라 설정을 수정하세요.

## 기록을 줄이는 사용법

- 홈에는 오늘의 일정 최대 3개, 캘린더 화면에는 오늘·이번 주·다음 주를 표시합니다. 화면의 시간 기준은 한국 시간입니다.
- 캘린더의 예정 시간은 실제 시간 통계에 자동 합산하지 않습니다.
- 일정이 끝나면 **실제 시간 확인**을 누릅니다. 제목·날짜·활동을 미리 채우고, 일정 길이는 참고값으로 보여줍니다. 실제 사용한 분을 확인·수정하고 저장해야 시간 통계에 반영됩니다.
- 미래 일정은 종료 전 실제 시간으로 가져오지 않습니다.
- 종일 일정과 24시간보다 긴 일정은 사용 시간을 직접 입력합니다. 종일을 24시간으로 계산하지 않습니다.
- 같은 일정은 중복 가져오지 않고 이미 저장한 기록을 열어 수정합니다. Google iCalUID가 있으면 여러 캘린더에 표시된 동일 초대 일정도 합칩니다. 반복 일정은 회차별로 구분합니다.
- Google에서 원본 일정을 수정해도 이미 확정한 실제 시간은 자동 변경하지 않습니다.

## 자동화의 범위와 저장

기본 연결은 Google GIS token model로 같은 탭의 연결을 복원합니다. 장기 연결은 별도 Supabase 함수로 갱신하며, 앱이 열려 있을 때 5분 간격과 화면 복귀 시 원본을 다시 조회합니다. 앱을 닫은 동안 데이터를 저장하는 백그라운드 동기화는 하지 않습니다.

- Google access token은 현재 탭의 sessionStorage에 계정·클라이언트·만료일과 함께 저장합니다. localStorage·일기 계정 JSON·백업 파일에는 저장하지 않습니다. 장기 연결의 refresh token은 서버 전용 테이블에 암호화합니다.
- 같은 탭의 새로고침은 유효한 세션을 복원합니다. 장기 연결 설정 후에는 토큰을 자동 갱신합니다. 로그아웃·연결 해제 시 탭의 토큰을 지우며, Google 동의 만료·취소 시에는 다시 연결해야 합니다. 사용자 동의 창을 자동으로 열지 않습니다.
- Google 계정 권한을 추가로 설정하지 않아도 다른 기록 화면과 Supabase 저장은 계속 사용할 수 있습니다.
- 캘린더 원본은 읽기만 하며 작성·수정·삭제하지 않습니다. 일반 일정의 세부 설명·참석자 목록·Gmail·연락처는 요청하지 않습니다. 메모로 지정한 캘린더만 메모 본문(description)을 함께 조회하고, 확인 후 기록으로 저장할 때만 보관합니다.
- 조회한 일정은 메모리에만 보관합니다. 사용자가 확인해 가져온 실제 시간 기록과 원본 식별 정보만 기존 서버 기록에 저장합니다.
- 앱 계정 전환·로그아웃 때 Google 토큰과 조회한 일정을 비우고 이전 요청을 취소합니다. 계정 A의 Google 정보를 계정 B 화면에 남기지 않습니다.
- 연결 해제 때 이 앱의 메모리를 비우고 Google에 토큰 취소를 요청합니다. 네트워크 문제로 취소 요청이 실패할 수 있으므로 Google 계정의 앱 권한도 직접 관리할 수 있습니다. 이미 확인한 실제 시간 기록은 유지됩니다.

## 검증 결과와 제한

공식 API/인증 문서를 직접 확인했습니다. 브라우저 테스트에서는 인증·API 응답을 모사하여 다음을 검증했습니다.

- 두 읽기 전용 범위만 요청, Calendar API는 GET만 사용
- 캘린더 목록·일정 목록 페이지 처리, 한국 시간, 취소 일정 제외
- 미래 일정 가져오기 차단, 종일의 실제 분 직접 입력
- 실제 시간 확인 전 자동 저장 없음, 역할 매핑, 중복 방지, 원본 메타데이터 편집 보존
- 일부 캘린더 조회 실패 안내, 읽기 권한 거절, 팝업 취소, 토큰 만료
- 탭 세션 복원, 일반 계정 데이터·localStorage·백업에 토큰 없음, 계정 전환 시 분리
- 로그아웃·앱 계정 전환 이후 늦게 도착한 Google 인증 응답 무시, 모바일 레이아웃
- 기존 Supabase 로그인·서버 저장·충돌/복구 테스트 및 PostgreSQL 권한 테스트 통과

실제 Google 계정의 일정 조회는 아직 검증하지 못했습니다. 공개 OAuth 클라이언트 ID와 본인 동의가 남아 있습니다. 테스트는 실계정 연결 성공이나 배포 완료를 대신하지 않습니다.

## Google Tasks 추가 — 확인하고 반영

Google Tasks도 사용할 경우 같은 Google Cloud 프로젝트에서 **Google Tasks API**를 추가로 사용 설정합니다.

- 활성화 페이지: https://console.cloud.google.com/apis/library/tasks.googleapis.com
- Google Auth Platform의 데이터 액세스 범위에 `https://www.googleapis.com/auth/tasks.readonly`를 추가합니다.
- 새 Client secret이나 별도의 Supabase SQL은 필요 없습니다. 같은 공개 OAuth 클라이언트 ID를 사용합니다.
- 앱의 연결 설정에서 **Google Tasks 할 일도 읽기 전용으로 연결**을 선택하거나, 캘린더 연결 후 **Google Tasks 연결**을 누릅니다. 추가 읽기 동의는 사용자가 버튼을 눌렀을 때만 요청합니다.
- Tasks 권한을 거절해도 Calendar의 두 읽기 권한이 있으면 캘린더는 사용할 수 있습니다. Tasks API 오류도 일정 조회를 막지 않습니다.

### Google Tasks를 원본으로 쓰는 흐름

1. Google Tasks에서 할 일을 작성합니다.
2. 하루에서 읽어온 목록은 **검토 대기**로 표시됩니다. 이 단계에도 개요의 Google 조회 현황에 자동 표시하지만 내 기록은 확인 후 저장합니다.
3. **확인하고 반영**을 눌러 제목·활동·기한·본업/알바 등 구분·메모·완료 여부를 확인합니다.
4. **확인한 내용만 반영**을 눌러야 내 업무에 저장됩니다. 취소하면 아무것도 저장하지 않습니다.
5. 원본이 바뀌면 **변경사항 검토**에서 다시 확인합니다. 동일한 Google Tasks 항목은 새로 추가하지 않고 기존 기록을 수정합니다.

현재는 Google Calendar와 Tasks 모두 읽기 전용입니다. 하루에서 업무를 수정하거나 완료해도 Google Tasks 원본으로 쓰지 않습니다. 원본 삭제·완료·기한 변경도 사용자 확인 없이 내 기록을 덮어쓰지 않습니다.

미완료 할 일을 기본으로 조회합니다. Google 웹·모바일 앱에서 완료한 항목도 보려면 **완료한 할 일도 보기**를 선택합니다. API의 `showCompleted`와 `showHidden`을 함께 켭니다. 목록이 너무 많으면 표시할 목록을 좁히거나 미완료만 조회하세요. Tasks 기한은 날짜이며, 시각이나 한국 시간으로 재변환하지 않습니다.

Tasks 조회 결과는 페이지 메모리에만 있고, OAuth 접근 토큰은 현재 탭의 세션 저장소에 만료 시까지 보관합니다. 확인한 업무와 원본 식별 정보만 기존 Supabase 일기 기록에 저장합니다.

## 알바 기록

캘린더의 끝난 일정에서 **실제 시간 확인 → 기록 분류: 알바**를 선택합니다. 활동과 제목·날짜를 확인하고 실제 근무한 분을 입력합니다.

- 알바명·근무처와 시급은 선택 항목입니다.
- 휴게시간을 제외한 실제 근무시간을 직접 확인합니다.
- 예상 금액은 `실제 분 ÷ 60 × 입력 시급`을 원 단위로 반올림한 값입니다.
- 시급을 적지 않은 기록을 0원 수입으로 판단하지 않습니다. 합계는 시급을 입력한 기록만 계산하고 입력 건수를 표시합니다.
- 세금·수당·계약 조건은 자동 계산하지 않으며 실제 입금이나 확정 급여가 아닙니다.
- 업무 화면의 **알바 기록**에서 날짜별 내역, 이번 달 실제 시간, 시급 입력분의 예상 금액을 봅니다. **알바 기록 ＋**로 직접 입력할 수도 있습니다.
- 실제 시간을 수정하면 예상 금액도 다시 계산합니다. 실제 수입 데이터에 자동 입금 기록을 만들지 않습니다.
- Google Tasks에서 알바 준비를 완료했다고 근무시간·예상 수입을 자동 생성하지 않습니다.

| 일정 제목 | 제안하는 총 수입 |
| --- | ---: |
| `[알바] 투자 심사 (50)` | 500,000원 |
| `[알바] 멘토링 (50만원)` | 500,000원 |
| `[알바] 강의 (50.5)` | 505,000원 |
| `[알바] 발표 (500,000원)` | 500,000원 |
| `[알바] 금액 미정 (?)` | 자동 추정하지 않음 · 확인창에서 직접 입력 |

`[알바]`가 없는 일반 일정의 `(50)`은 금액으로 해석하지 않습니다. 음수·잘못된 쉼표·과도한 소수점·인원 단위 등 확실하지 않은 값도 0원으로 바꾸지 않습니다. 기본 활동은 사용자 규칙에 따라 투자 회사로 제안하되 확인창에서 바꿀 수 있습니다.

1. 캘린더 카드에 **수입 후보**가 표시됩니다. 아직 통계에 합산하지 않습니다.
2. **수입 확인**에서 원본 제목, 총액(원), 수행일, 활동, 예정/확정 상태를 확인합니다.
3. **확인한 수입 저장** 후에만 돈 화면의 월별 추가 알바 수입에 반영합니다.
4. 입금이 확인되면 별도로 **입금 완료**와 실제 날짜·금액을 기록합니다. 수입을 확정했다고 자동으로 입금 처리하지 않습니다.

현재 월과 지난 달의 알바 일정을 한 번에 검토할 수 있도록 캘린더에 **이번 달 / 지난 달**도 추가했습니다. 미래 일정은 기본 상태가 **예정**이며 미래 수행일을 확정 수입으로 저장할 수 없습니다. 단, 실제 수행일을 과거로 수정해 본인이 확인한 수입을 기록할 수는 있습니다.

### 월별 기준

- **수행월 기준 확정 수입**: 그 달에 수행했다고 확인한 추가 알바 수입. 미등록 월급 등 모든 소득을 뜻하지 않습니다.
- **입금월 기준 실제 입금**: 실제 입금일과 금액을 확인한 기록만 집계합니다.
- 예정 수입과 미입금은 따로 표시합니다. 예정 수입은 확정 수입에 포함하지 않습니다.
- 예를 들어 1월에 수행한 50만원이 2월에 483,500원 입금됐다면, 1월의 확정 수입은 500,000원, 2월의 실제 입금은 483,500원입니다. 세금 차감은 앱이 추정한 것이 아니라 입력한 금액의 차이입니다.
- 월 선택과 연도별 12개월 비교를 제공하며, 홈에도 이번 달 확정 추가 수입과 실제 입금이 표시됩니다.
- 한 수입 건의 최종 입금 날짜·금액 한 건을 기록합니다. 다회 분할 입금, 세금·수당·급여명세를 자동 관리하는 기능은 아닙니다.

시간 기록과 수입은 서로 독립적입니다. 수입만 확인해도 근무시간을 생성하지 않고, 제목의 총액을 시급에 다시 곱하지 않습니다. 같은 캘린더 원본에서 시간 기록을 먼저 만들거나 수입을 먼저 만들어도 수입은 한 건만 유지합니다. 원본 제목이 바뀌어도 기존 확인 금액은 자동 변경하지 않으며 다시 검토해 수정합니다.

수입 화면에서도 직접 추가·수정·삭제할 수 있습니다. 지출 가계부는 추가하지 않았습니다. 같은 기존 `incomes` 저장소를 사용하므로 새 Supabase SQL은 필요 없습니다.

추가 검증: `node tests/income-format.cjs`, `node tests/calendar-income.cjs`에서 단위·소수·쉼표·금액 미정, 사용자 확인, 수행월/입금월 분리, 실제 입금액, 시급 중복 계산 방지, 미래 예정 제외, 새로고침과 모바일을 확인했습니다. 실제 Google 계정 조회나 원격 게시는 여전히 별도입니다.

## 상세 시간 분석

홈의 ‘내 캘린더·상세 시간 분석’ 또는 캘린더의 ‘상세 시간 분석’ 탭에서 활동별·날짜별·시간대별로 확인합니다. 홈은 짧은 요약과 미리보기만 보여줍니다. 지출 가계부는 여전히 추가하지 않았습니다.

- 일정 확인창에서 ‘실제 시작·종료까지 확인’을 선택해야 시각까지 저장합니다. 선택하지 않으면 실제 분만 저장하고 위치를 추정하지 않습니다.
- 직접 시간 기록의 시각 필드도 선택 항목으로 접어두었습니다. 실제 분과 구간이 다르면 휴게시간을 나눠 기록하거나 시각을 비워주세요.
- 예정은 연한 테두리, 시각을 확인한 실제 구간은 진한 색으로 별도 표시합니다. 실제 구간을 누르면 해당 기록을 수정할 수 있습니다.
- 분 합계·겹침 제외 시간·종일 제외 예정·시각 미확인 분을 구분하고 겹친 실제 구간을 표시합니다.
- 경과한 부분에서만 시각 미확인 구간을 구합니다. 수면·휴식 등일 수 있으며 ‘낭비’로 해석하지 않습니다.
- 임의의 월 선택을 지원합니다. 해당 기간 Google 조회가 안 됐다면 실제 저장 기록만 보이고 예정 수치를 0으로 확정하지 않습니다.
- 실제 시각과 분은 기존 timeLogs의 선택적 문자열 필드에 보관합니다. 추가 Supabase SQL은 필요 없습니다.

배포 파일에 `time-stats.js`도 포함해야 합니다. 개발 변경은 로컬에만 준비했으며 게시하지 않았습니다.


## 요약 화면·숨기기·시각형 캘린더

홈에서는 오늘 일정과 Tasks 중 아직 반영하지 않은 항목을 각각 최대 2개 표시합니다. 확인한 시간 기록/업무는 홈 검토 대기에서 빠집니다. 숨기기는 계정별 Google 연결 설정의 `hiddenItems`에 저장해 다른 기기에도 반영하고, 캘린더 탭의 ‘숨긴 항목’에서 복원합니다. 원본 삭제·기존 확정 기록 삭제·시간 통계 계획 데이터 제외를 뜻하지 않습니다.

캘린더는 주간 시간표(겹친 일정 분리, 자정 넘김 구간 분리, 종일 별도 행)와 날짜별/월간 보기를 제공합니다. 일정을 눌러 상세를 보고 기존 실제 시간·수입 검토 화면으로 반영할 수 있습니다. 시각화에서 직접 드래그하거나 Google에 쓰지는 않습니다.

검증: `tests/google-ui.cjs`는 홈 요약, 숨기기/복원, 새로고침, 시각화, 계정 세션, 모의 서버 갱신을 확인합니다. `tests/google-server.cjs`는 서버 핸들러를 Node에서 실행해 상태 일회성·암호화·계정 권한·토큰 회전/해제를 모의 검증합니다. 실제 Supabase 함수 배포와 실제 Google 장기 연결 성공을 대신하지 않습니다.


## 메모 캘린더 분리

캘린더 이름이 정확히 `메모`이면 기본적으로 메모로 분류합니다(앞뒤 공백 무시). 연결 설정의 캘린더별 ‘표시 방식’에서 일정/메모를 직접 선택할 수 있으며, 선택은 계정에 저장됩니다. 업무/개인/가족 등 다른 캘린더는 일정으로 유지합니다. 기존 표시할 캘린더 선택은 유지하므로 메모를 아직 선택하지 않았다면 표시 체크를 켜주세요.

메모는 홈의 오늘 메모(최대 2개)와 캘린더의 날짜별 메모로 분리합니다. 주간/월간 시간표, 예정 시간 통계, 실제 시간 가져오기, 알바 수입 후보에서 제외합니다. 기존에 이미 확인해 저장한 시간 기록을 임의로 삭제하거나 바꾸지는 않습니다. 메모도 숨기기/복원이 가능합니다.

‘기록으로 가져오기’에서 내용을 확인한 뒤 자유 기록(notes)으로 저장하며, 구글 식별자로 중복을 방지합니다. 미래 원본 메모는 내 기록 날짜를 오늘로 제안하고 원본 날짜는 googleMemoDate로 보관합니다. 원본 Google 메모는 수정하지 않습니다. 확인해 저장한 뒤의 원본 변경은 자동 덮어쓰지 않습니다. 메모 본문은 HTML을 실행하지 않고 텍스트로 표시합니다.

검증: `tests/google-memos.cjs`에서 자동 분류, 본문 조회 범위, 시간·수입 제외, 확인 후 저장/중복 방지, 미래 날짜, 숨기기/복원, 설정 변경, 계정 저장과 모바일을 확인합니다.


## 업무·목표·시간에 연결하기

1. **캘린더 선택/연결 설정**에서 각 캘린더의 기본 활동과 기본 목표를 선택합니다. 메모 캘린더는 시간 통계에서 계속 제외합니다.
2. **Tasks 목록 선택**에서도 기본 활동과 목표를 정합니다. 목표에 소속 활동이 있으면 그 활동을 따릅니다.
3. 개요·업무·목표의 완료 단계/예정 시간은 조회 즉시 표시됩니다. 실제 시간은 자동 생성하지 않고 종료된 일정의 길이를 ‘지난 일정 기준 추정’으로 별도 표시합니다.
4. 개별 일정의 **활동·목표 연결**은 미래에도 수정할 수 있고 목표 연결을 비울 수도 있습니다. 실제 시간 저장 시와 Tasks 반영 시에도 목표를 선택/수정할 수 있습니다. 이미 반영한 내 업무의 수정을 원본 조회로 덮어쓰지는 않습니다.

Google 완료 항목도 집계하기 위해 선택한 Tasks 목록의 완료/숨긴 완료 항목을 함께 읽습니다. 화면의 미완료 필터는 표시만 바꾸고 개요 집계에는 영향을 주지 않습니다. 이미 저장한 같은 Tasks는 내부 값이 우선이고 원본 완료 상태 변경은 별도 검토합니다. Google 쓰기 권한은 추가하지 않습니다.
